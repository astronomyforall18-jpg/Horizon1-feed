### [vLLM Adds Day-0 Support for Thinking Machines' Looped Inkling 2 Mini Model](https://vllm.ai/blog/2026-11-20-inkling2-mini) ⭐️ 8.0/10

rss · vLLM Blog · Nov 20, 00:00

**「Background」** Thinking Machines introduced Inkling 2 Mini, a multimodal mixture-of-experts model featuring a looped architecture where middle layers run multiple passes per token. Integrating this novel recurrence pattern presented unique memory and execution challenges for standard inference frameworks.

**「Architecture and vLLM Integration」** Inkling 2 Mini splits its 24 layers into a prelude, a loop core \(layers 6–17 running three passes with shared weights\), and a coda. Each core sublayer reads gated messages from the previous pass using a rank-64 controller and maintains independent KV and conv-state caches. To achieve day-0 support on NVIDIA Blackwell, Hopper, and DGX Spark, vLLM registers each extra core pass as a standard attention layer, allowing its cache manager and prefix caching to handle them without modification. Performance is optimized by fusing message reads and stacking controller weights into batched GEMMs, using Triton kernels for RMS normalization, and reusing fused kernels from Inkling 2 Small. Additionally, vLLM supports a variable-loop research checkpoint \(TML-d24-varloop-research\) via configuration overrides, allowing users to adjust the number of passes or share KV caches across passes. Benchmarks on a single GB200 show decode step times ranging from 1.51 ms to 3.85 ms for batch size 1 across different pass configurations, while maintaining numerical alignment with the reference implementation.

**「Takeaway」** vLLM successfully accommodates non-standard model recurrence and per-pass memory layouts through specialized kernel fusion and modular cache registration.

**Tags**: `#vLLM`, `#LLM Inference`, `#Model Architecture`, `#Kernel Optimization`
