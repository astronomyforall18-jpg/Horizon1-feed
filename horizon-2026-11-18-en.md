### [Unauthenticated Remote Code Execution Vulnerabilities Discovered in Nginx HTTP/2 Handling](https://www.wiz.io/blog/nginx-http2-rce-vulnerabilities) ⭐️ 9.0/10

Security researchers analyzed unauthenticated remote code execution vulnerabilities in Nginx related to HTTP/2 handling, tracked as CVE-2026-123633 and CVE-2026-123007. The discovery affects web systems utilizing Nginx with HTTP/2 enabled, prompting widespread discussion regarding disclosure timelines and mitigation steps.

hackernews · speedping · Nov 18, 15:19 · [Discussion](https://news.ycombinator.com/item?id=50547374)

**「Background」** Nginx is a widely used open-source web server and reverse proxy that handles incoming web traffic and supports the HTTP/2 protocol.

**「Impact」** Administrators running affected Nginx configurations can mitigate the risk by disabling HTTP/2, as the protocol is not enabled by default and is utilized by an estimated 12% of servers.

**「Community Discussion」** Community members debated disclosure timelines, noting that fixes appeared in the open-source repository a week before public advisories, potentially exposing unpatched systems during that window. Commenters also highlighted that since HTTP/2 is not enabled by default, exposure is limited to servers explicitly configured to use it.

### [Simon Willison and Prime Radiant Introduce External Sandbox Pattern for AI Coding Agents](https://simonwillison.net/2026/Nov/17/external-sandboxes-for-coding-agents/) ⭐️ 8.0/10

Simon Willison and AI research lab Prime Radiant introduced the external sandbox architectural pattern to execute code generated by AI coding agents safely. The pattern separates the agent environment from the code execution sandbox to prevent model errors or prompt injection attacks from damaging the host machine. Alongside the announcement, three open-source sandbox server implementations utilizing WebAssembly, Apple Containers, and Microsoft's Quicksand library were released with a shared localhost API. The sandboxes feature an optional HTTP/HTTPS allow-list proxy and a credential replacement mechanism for controlled network access.

rss · Simon Willison · Nov 17, 22:52

**「Background」** AI coding agents execute code generated by language models, which introduces risks such as unintended destructive commands or prompt injection vulnerabilities. Prime Radiant is an AI research lab known for projects including Superpowers.

**「Impact」** Developers using tools like Pi, Claude Code, or Codex can configure them to route execution calls through the newly released external sandbox servers, isolating untrusted code execution and enforcing network destination controls via an HTTP/HTTPS allow-list proxy.

### [Keeping Agents Fast: High-Interactivity Decode with FlyDSL MonoKernels in vLLM](https://vllm.ai/blog/2026-11-18-flydsl-monokernels) ⭐️ 8.0/10

rss · vLLM Blog · Nov 18, 00:00

**「Background」** Interactive LLM applications and coding agents require low decode latency, which sits on the critical path of task execution. At low concurrency, a standard decode step executes a chain of GPU kernels where startup, dispatch, and completion overheads limit performance and leave hardware capacity underutilized.

**「Solution」** To eliminate inter-kernel wait times, FlyDSL MonoKernels combine multiple dependent operator stages into persistent GPU kernel launches for vLLM on AMD Instinct GPUs. Inspired by TileRT, the approach employs a fixed grid of thread blocks that reuse blocks across stages, prefetch weights during earlier computations to overlap HBM traffic, and hand off data to consumers via tagged mailboxes as soon as it is ready. Kernel authors design models-specific boundaries and schedules using FlyDSL, controlling data movement, tensor layouts, and synchronization down to individual buffer and matrix instructions. Compiled and cached via @flyc.kernel and @flyc.jit, these specialized decode paths integrate into vLLM as an opt-in feature managed per layer and step, seamlessly supporting HIP graphs and speculative decoding. Evaluations on MI325X and MI355X hardware demonstrate substantial improvements in interactivity and time-per-output-token across models such as DeepSeek-V4.1-Flash, MiniMax-M3, Kimi-K3, and Muse Spark, while maintaining accuracy within statistical noise.

**「Takeaway」** FlyDSL MonoKernels effectively reduce small-batch decode latency in vLLM by fusing dependent operator stages into persistent GPU launches that maximize hardware utilization and interactivity.

**Tags**: `#GPU optimization`, `#LLM serving`, `#vLLM`, `#kernel fusion`
